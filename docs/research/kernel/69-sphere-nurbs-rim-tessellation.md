# 69. NURBS-rim sphere tessellation watertightness: edge-conforming band meshing at the shared seam with the cyl / cone wall

## Title and scope

This is the implementation-grade literature dossier for **the edge-conforming tessellation of a sphere face trimmed by general NURBS rims**, the confirmed watertightness gap named at Add.283. It is the tessellation-side companion to dossier 64 (the seam-aware periodic-domain SPLIT, which produces the trimmed band as a topological face) and to dossier 63 (the curvature-adaptive density and the mass-vs-mesh gate). This dossier does NOT re-derive the periodic-domain arrangement (64 owns that), the sagitta / segment-count density rule, the inscribed-undercount volume bias, or the analytic mass reference (63 owns those). It answers the one orthogonal question those deferred: **once the boolean has produced a sphere BAND bounded by two non-planar NURBS rims (the band's two rims shared with the cyl / cone wall), how is that band tessellated so that (a) the mesh of the shared rim is the SAME point set the wall returns, making `mesh_open_ratio` ~ 0 by construction, and (b) the interior is meshed so `mass == mesh` within the 2 percent curved band, for all three boolean ops and across arbitrary sphere frames.**

**Where Keel is (grounding, build on, do not re-research).** Tolerant-f64 non-manifold radial-edge B-rep. `mesh_volume` tessellates each face and sums signed tetrahedra (divergence theorem on the mesh); the `mass == mesh` gate uses a 2 percent curved band; `mesh_open_ratio` measures watertightness, requiring that shared edges yield identical point sets. `tessellate_sphere` (in `tessellate.rs`) currently has a circle-rim clip plus the single-window-disc fan (Add.281: a fan from an on-surface anchor to the loop's canonical `fin_curve_samples`, watertight because a shared seam edge yields the SAME point set, just forward-reversed). ALREADY LANDED, do not re-derive: `tessellate_cylinder` has an even-odd `(theta, h)` STENCIL for degree>=2 NURBS-trimmed faces (the general analog of the sphere multi-rim clip). A sphere face is ONE periodic `(u, v)` domain: `u` in `[0, 2*pi)` seam-identified at the slit, `v` in `[-pi/2, +pi/2]` with both ends contracted to the poles. **THE GAP (confirmed, Add.283):** a general NURBS WRAP rim has NO path in `tessellate_sphere`, so a non-coaxial sphere-vs-{cyl, cone} wrap meshes to the full sphere or overshoots, and the shared edge with the cyl / cone wall is non-watertight, so the watertightness net declines (the dominant ~9200 post-Add-294 decline). The cyl / cone wall returns the SAME rim points (canonical `fin_curve_samples`). DEAD END, do NOT propose: the circle-rim-specific clip is the exact thing being generalised.

## The load-bearing conclusion, stated once

> **The watertight sphere-band mesh is NOT a clip of the full-sphere grid against the rim, and it is NOT a fan from a single anchor. It is a STENCIL in the `(u, v)` rectangle (the direct sphere analog of the landed `tessellate_cylinder` even-odd `(theta, h)` stencil): build the same canonical interior grid the full sphere would use, classify each grid point by an even-odd ray test against the two rim pcurves lifted to `(u, v)`, keep the interior grid points strictly between the two rims, and SEAM the boundary band of triangles to the rims' canonical `fin_curve_samples` polylines, which are the EXACT SAME point sets the cyl / cone wall meshes from. The watertightness is by construction and identical in kind to the Add.281 window-disc: a shared rim edge is meshed ONCE into a canonical ordered polyline that is stored on the EdgeId, and BOTH the band face and the wall face read that same polyline (the band reads it forward along one rim and reversed along the other, the wall reads it reversed). Because both faces emit the identical vertex sequence on the shared edge, `mesh_open_ratio` is zero with no merge / weld / heal step. The interior rows are FACE-PRIVATE: they never appear on any shared edge, so their density is free to be chosen per-face for the `mass == mesh` gate without coordinating with the wall. The whole construction reduces to three sub-mechanisms, each already proven in Keel or in the cited production literature: (1) the canonical per-edge rim polyline shared by both incident faces (Add.281 window-disc, the OCCT / Patrikalakis edge-discretized-once rule); (2) the even-odd `(u, v)` stencil that decides which interior grid points survive (the landed cylinder stencil, the classical scanline / point-in-polygon trimmed-NURBS rule); (3) the seam-and-pole bookkeeping of the periodic rectangle (dossier 64's identification / contraction model). The band is then meshed as the region BETWEEN the two rim polylines, exactly the "strip between two boundary curves" construction, with the rim polylines fixed and only the interior densified.**

The defensible reason, in one paragraph. Watertightness across a shared edge is a discrete equality, not a geometric tolerance: two faces are sealed along an edge if and only if they emit the SAME sequence of 3D points on that edge. Every production faceter that achieves watertight output enforces this by discretizing each model edge ONCE and forcing both incident face meshes to use that one discretization (OCCT's `BRepMesh_EdgeDiscret` computes one tessellation per edge and both faces reference it; Patrikalakis-Marshall discretize the shared boundary curve once and transfer the SAME polyline to the mate segment; Marechal-style sealing merges boundary points so adjacent patches coincide). Keel already does exactly this for the window-disc case via the canonical `fin_curve_samples` stored on the EdgeId, and the Add.281 fan is watertight precisely because the disc reads that one polyline. The ONLY thing missing for the band is the interior fill BETWEEN two such shared rims, and that fill is a face-private mesh whose sole watertightness obligation is to TERMINATE on the two canonical rim polylines without introducing new points on them. The even-odd stencil is the mechanism that selects which canonical interior grid points lie in the band, and the boundary-band triangulation is the mechanism that joins the kept interior points to the fixed rim polylines. Neither touches the shared-edge point sets, so neither can break watertightness. The interior density is then a pure `mass == mesh` question, answered by dossier 63's machinery (analytic sphere-zone reference, sagitta density, no coupling to the wall). The non-coaxial NURBS wrap is therefore not a new geometric problem; it is the cylinder stencil re-expressed on the sphere's doubly-contracted rectangle, with the seam slit and the two poles handled by dossier 64's identification / contraction flags.

The one honest caveat. A handful of configurations are genuinely unmeshable as a single band and stay DECLINE-forever (Q4 of dossier 64, repeated here for the tessellation view): a rim tangent to a pole, a rim whose `(u, v)` preimage self-crosses, a sub-tolerance sliver band, a rim that passes through the seam slit at a point coincident with a pole. Those decline loudly, never WRONG. Everything else in the sphere-wrap frontier flows through the one stencil.

## Q1. The band mesh: the edge-conforming strip between two non-planar NURBS rims

### Q1.0 The deliverable, stated as a construction

The band is the region of the sphere `(u, v)` rectangle BETWEEN two encircling rim pcurves `c_lo(u)` (the lower rim, smaller `v`) and `c_hi(u)` (the upper rim, larger `v`). Both rims are shared edges with the cyl / cone wall and carry a canonical `fin_curve_samples` polyline on their EdgeId. The band's mesh is: the two fixed rim polylines (forward on one, reversed on the other, the shared-edge obligation), plus a face-private interior grid clipped to lie strictly between the rims, plus a boundary band of triangles joining the interior grid to each rim polyline. Interior rows are NOT shared with any other face, so their count and placement are free.

### Q1.1 The row / column construction and orientation

> **Citation.** Reconstruction from the landed Keel cylinder stencil (Add, `tessellate_cylinder` even-odd `(theta, h)` stencil), the Add.281 window-disc canonical-polyline rule, dossier 64 Q1.3 (sphere identification / contraction domain), and the "strip between two parametric curves" ruled-mesh construction (Lai et al., strip parameterization; ScienceDirect ruled-surface strip filling). https://cg.cs.tsinghua.edu.cn/people/~laiyk/papers/tase08strip.pdf
> **Method / Content (the recommended Keel mechanism).**
> Domain: `u` in `[0, 2*pi)` identified at the seam slit, `v` in `[-pi/2, +pi/2]` with both `v`-edges contracted to poles. The band lies in `v_lo(u) <= v <= v_hi(u)` where `v_lo`, `v_hi` are the two rim pcurves (each a single-valued, `u`-monotone wrap after the dossier-64 split-at-v-extrema; a non-monotone wrap is split into `u`-monotone sub-arcs first).
> 1. **Fix the two rim polylines (shared, do not resample).** Read each rim's canonical `fin_curve_samples` from its EdgeId: an ordered sequence of 3D points `R_lo[0..m_lo]` and `R_hi[0..m_hi]`, with their `(u, v)` preimages. These were produced ONCE (at imprint / split time) and are the SAME sequence the cyl / cone wall meshes from. The band consumes them verbatim. This is the ONLY watertightness-load-bearing data in the whole mesh.
> 2. **Build the canonical interior `u`-columns.** Use the SAME azimuthal sample set the full sphere would use: `u_j = j * (2*pi / N_u)`, `j = 0..N_u-1`, with `N_u` the canonical sphere longitude count (dossier 63 sagitta rule, `N_u = ceil(pi / acos(1 - tol/R))`). Using the canonical column set (not a per-band ad-hoc set) is what makes neighbouring bands and caps on the same sphere share interior column positions where they meet at the seam slit, and keeps the stencil deterministic.
> 3. **Build the interior `v`-rows, clipped per column.** For each canonical column `u_j`, the band occupies the `v`-interval `[v_lo(u_j), v_hi(u_j)]`. Place `N_v` interior rows in that interval (uniform in `v`, or dossier-63 latitude-adaptive). These row vertices are FACE-PRIVATE. The first and last interior rows sit slightly inside the rims (offset by the row spacing), NOT on them; the gap to the rim is closed by the boundary band (step 5).
> 4. **Even-odd keep test (the stencil, Q2).** A canonical grid vertex `(u_j, v_k)` is KEPT iff it lies strictly between the two rims at that column, i.e. `v_lo(u_j) < v_k < v_hi(u_j)`, which the even-odd ray test (Q2) computes uniformly even when a rim dips below another column's range. Interior quads between kept vertices are split into two triangles each; a quad with any corner outside is handled by the boundary band.
> 5. **Boundary band: seam interior to the fixed rim polyline.** Along each rim, zipper the rim polyline `R` to the adjacent kept interior row by the standard two-pointer strip merge between two polylines of unequal length: advance whichever of (rim index, interior index) is "behind" in `u`, emitting a triangle each step, so every rim vertex and every adjacent interior vertex is used exactly once and no T-junction is left. This is the ruled-strip "link points of equal parameter, fill with rulings" construction generalised to unequal counts. The rim polyline vertices are emitted UNCHANGED (no new points inserted on the rim), preserving watertightness.
> 6. **Seam-slit closure.** The band wraps the full `u`-period, so column `u_0 = 0` and the wrap-around to `u = 2*pi` are the SAME meridian. Close the last interior quad-row from `u_{N_u-1}` back to `u_0` using the identified seam: the two `u`-edges map to the same 3D meridian, so the closing triangles reuse the `u_0` column vertices (no duplicate seam vertices). This is dossier 64's identification boundary applied to the mesh, not just the topology.
> 7. **Orientation.** Emit every triangle with outward winding consistent with the face's `sense * natural` normal (the massprops resolution in MEMORY): for a sphere the natural normal is radially outward, so order each triangle's vertices counterclockwise as seen from outside. The lower rim is traversed forward and the upper rim reversed (or vice versa) so the band's outer loop is a single consistently-oriented cycle, matching the dossier-64 band loop orientation. The shared rim's coedge sense on the band is OPPOSITE the wall's coedge sense on that same EdgeId (radial-cycle-2 pairing), which the mesh respects automatically because each face emits the shared polyline in its own loop direction.
> **Limitations.** Assumes the two rims are disjoint, each `u`-monotone (after v-extrema split), and order-able in `v` so "between" is well defined. Mutually intersecting rims, or a rim that locally exits and re-enters the band, need the full `(u, v)` arrangement face walk (dossier 64 Q1.5 A) feeding per-region stencils. A rim tangent to a pole is Q4.
> **Kernel relevance.** This IS the missing `tessellate_sphere` path. It is the cylinder stencil with two changes: the `v`-rows are clipped per-column to the band interval (cylinder rows were full-height), and both `v`-ends can be a contracted pole (cylinder had none). The interior-private / rim-shared split is the exact Add.281 invariant extended from one window rim to two band rims. **Claimed** as the recommended construction, validated by Q4.

### Q1.2 Why interior rows are face-private (the load-bearing simplification)

> **Citation.** OCCT `BRepMesh` two-stage model (edges discretized first, faces filled second), https://dev.opencascade.org/doc/overview/html/occt_user_guides__mesh.html ; Patrikalakis-Marshall edge-once transfer (Q3.1); Add.281 (Keel internal).
> **Method / Content.** Production faceters separate edge discretization from face filling precisely so that the only shared data is the edge polylines and everything inside a face is private. OCCT computes `BRepMesh_EdgeDiscret` for every model edge FIRST, then each face's interior is filled against those fixed boundary discretizations. The interior nodes of one face never appear on a neighbour, so their density is a per-face decision. Keel's band inherits this directly: the two rim polylines are the fixed shared boundary; the interior grid and rows are private; therefore the `mass == mesh` density question (dossier 63) is answered per-band with zero watertightness coupling to the wall. This is what lets the band be densified for the mass gate without ever renegotiating the shared rim with the cyl / cone wall.
> **Limitations.** The face-private interior must still terminate cleanly on the fixed rim (the boundary band, Q1.1 step 5); a careless interior fill that inserts a vertex ON the rim would break the invariant. The construction forbids inserting rim vertices.
> **Kernel relevance.** Names the invariant that makes the whole thing tractable: shared = rim polylines only; everything else private. **Verified** against the OCCT two-stage model and the Add.281 precedent.

## Q2. The general NURBS-trim path: the even-odd `(u, v)` stencil

### Q2.1 The stencil as the sphere analog of the landed cylinder stencil

> **Citation.** Landed Keel `tessellate_cylinder` even-odd `(theta, h)` stencil (internal); even-odd rule / Jordan curve theorem, https://en.wikipedia.org/wiki/Even%E2%80%93odd_rule ; point-in-polygon ray crossing, https://en.wikipedia.org/wiki/Point_in_polygon ; Hormann-Agathos point-in-polygon for arbitrary polygons, https://www.inf.usi.ch/hormann/papers/Hormann.2001.TPI.pdf ; "A Simple and Correct Even-Odd Algorithm for the Point-in-Polygon Problem for Complex Polygons", arXiv:1207.3502, https://arxiv.org/pdf/1207.3502 .
> **Method / Content.** The trimmed-surface tessellation primitive is: build the untrimmed parameter grid, then for each grid point decide inside / outside the trim loops by an even-odd ray test against the trim pcurves in parameter space, keeping the inside points and clipping the boundary cells. The even-odd (Jordan) rule: cast a ray from the test point in a fixed parameter direction (here, +`v` or +`u`), count crossings with the trim pcurve polylines; odd = inside the kept region, even = outside. Keel's landed cylinder stencil is exactly this on the `(theta, h)` rectangle for degree>=2 NURBS-trimmed cylinder faces. The sphere stencil is the SAME rule on the `(u, v)` rectangle, with two periodic-domain adaptations:
> - **Wrap-aware ray across the seam.** Cast the keep-test ray in +`v` (latitude), which never crosses the `u`-seam, so the seam identification needs no special ray handling for the interior test. (A +`u` ray would have to wrap the seam and count a crossing on re-entry; choosing the +`v` ray sidesteps that.) The rims themselves are stored as `u`-monotone wraps, so a vertical ray at `u_j` crosses `c_lo` exactly once and `c_hi` exactly once, giving the clean "inside iff below `c_hi` and above `c_lo`" parity for the two-rim band.
> - **Pole degeneracy.** At a contracted `v`-edge the whole `u`-row collapses to one point. A grid column whose interval reaches a pole (a CAP, not a band) is meshed by the existing window-disc fan to the pole anchor (Add.281), not by a quad row; the stencil flags such a column as pole-terminated and hands it to the cap path. The band path proper never reaches a pole (both its rims are interior to `v`).
> **Limitations.** The even-odd parity is robust only if the test ray avoids passing exactly through a rim vertex (a degenerate crossing); use the standard half-open edge convention (count a crossing iff the edge straddles the ray with a consistent endpoint rule, the arXiv:1207.3502 fix) to keep parity correct at shared `v` values. A rim tangent to the ray direction at a vertex needs the same convention. Self-crossing rim preimages break the simple parity and DECLINE (Q4 / dossier 64).
> **Kernel relevance.** This is the direct generalisation the prompt asks for: lift the landed cylinder `(theta, h)` even-odd stencil to the sphere `(u, v)` rectangle, wrap-aware via the +`v` ray and pole-aware via the cap handoff. The circle-rim clip is the special case where `c_lo`, `c_hi` are `v = const` latitudes; the stencil subsumes it without a circle-specific branch (which is the DEAD END being retired). **Claimed** as the recommended path; the even-odd rule and the half-open crossing convention are **verified**.

### Q2.2 Scanline fill of the kept region (the production trimmed-NURBS pattern)

> **Citation.** "A tessellation algorithm for the representation of trimmed NURBS surfaces with arbitrary trimming curves", Computer-Aided Design, 1995, https://www.sciencedirect.com/science/article/abs/pii/0010448595000437 ; "Efficient trimmed NURBS tessellation", https://www.researchgate.net/publication/221546526_Efficient_trimmed_NURBS_tessellation ; "Tessellation of Trimmed NURBS Surfaces using Multipass Shader", DLR, https://elib.dlr.de/100596/1/Geiger-Bachelorarbeit-2015-09-20.pdf .
> **Method / Content.** The classical trimmed-NURBS tessellation builds a uniform parameter grid, uses a SCANLINE algorithm to identify and fill the interior of the trim polygon (remove grid cells inside inner trimming loops / outside outer loops), and closes the boundary between the trim polyline and the interior grid with a set of boundary triangles. Counterclockwise trim loops retain the enclosed area, clockwise discard it (the standard orientation-as-fill-rule convention). The scanline is the row-wise application of the even-odd test: for each grid row (here, each canonical `u`-column scanned in `v`), the spans between odd and even crossings of the trim polylines are the kept intervals. This is precisely Q1.1 steps 3 to 5 expressed as a scanline: per column, the kept `v`-span is `[v_lo(u_j), v_hi(u_j)]`, interior rows fill it, and the boundary triangles join the span ends to the rim polylines.
> **Limitations.** The scanline assumes the trim polyline is a faithful, non-self-intersecting approximation of the trim curve at the grid resolution; a rim sampled too coarsely relative to the grid can miss a thin band and mis-classify (the rim must be sampled at least as densely as the grid `v`-spacing where it turns). Keel's canonical `fin_curve_samples` density is set at imprint time and must meet this; if not, the band declines rather than mis-fills.
> **Kernel relevance.** Confirms the band fill is the textbook trimmed-NURBS scanline (grid + even-odd keep + boundary triangles), with Keel's one twist being that the boundary triangles attach to a PRE-EXISTING shared rim polyline (not a freshly sampled trim edge), which is what buys watertightness. **Verified** as the standard trimmed-NURBS algorithm.

### Q2.3 The cap-with-NURBS-rim case (one rim, terminating at a pole)

> **Citation.** Add.281 window-disc fan (Keel internal); dossier 64 Q1.3 (sphere pole as single contraction vertex); sphere pole singularity handling, Hoffmann sphere tessellation, http://docs-hoffmann.de/ikos27042002.pdf .
> **Method / Content.** A non-coaxial sphere-vs-{cyl, cone} wrap that encloses a pole splits the sphere into a band PLUS two caps, where each cap is bounded by ONE NURBS rim and contains a pole. The cap is meshed by the SAME machinery as the band's pole-terminated columns: the kept interior region runs from the single rim up to the pole, and the interior is fanned to the pole anchor (Add.281 window-disc fan) while the rim side uses the boundary-band zipper (Q1.1 step 5) against the canonical rim polyline. The pole is a SINGLE shared vertex (dossier 64 contraction rule), used exactly once, so no doubled-pole cover. The cap is thus the union of (a) the boundary band against the fixed rim polyline and (b) the existing window-disc fan to the pole, with the kept interior grid between them.
> **Limitations.** A rim that comes within tolerance of the pole makes the fan triangles degenerate (near-zero area); evaluate the pole anchor perturbed slightly off the singularity (dossier 64 Q4) or DECLINE if within tolerance of passing through it.
> **Kernel relevance.** Shows the cap is not a new mechanism: it is the band's pole-terminated column handled by the already-landed window-disc fan, with the single NURBS rim treated by the same shared-polyline boundary band. **Claimed** (composition of two landed mechanisms), pole-as-single-vertex **verified** (dossier 64).

## Q3. Watertightness proof: identical point sets on the shared seam edge

### Q3.1 The shared-edge identity, extended from the window-disc to the band's two rims

> **Citation.** OCCT `BRepMesh_EdgeDiscret` (one tessellation per model edge, both faces reference it), https://dev.opencascade.org/doc/overview/html/occt_user_guides__mesh.html and the BRepMesh wiki, https://github.com/Open-Cascade-SAS/OCCT/wiki/mesh ; X. Marshall / N. M. Patrikalakis et al., "Robust tessellation of trimmed rational B-spline surface patches", 1998 (the common boundary curve is linearly approximated ONCE and transferred to the mate boundary segment), https://ieeexplore.ieee.org/document/694308/ ; Add.281 window-disc (Keel internal).
> **Method / Content (the proof).** Two faces sharing an edge `E` are watertight on `E` iff they emit the identical ordered 3D point sequence on `E`. The construction guarantees this structurally:
> - **One canonical polyline per edge.** `E`'s discretization is computed ONCE (at imprint / split time) and stored on the EdgeId as `fin_curve_samples`, an ordered sequence `P[0..m]`. This is the OCCT `EdgeDiscret` rule and the Patrikalakis edge-once-transfer rule, and it is exactly the Add.281 mechanism Keel already uses for the window rim.
> - **Both incident faces read that one polyline.** The band face reads `P` in its loop direction (say forward, `P[0], P[1], ..., P[m]`); the cyl / cone wall reads the SAME `P` in ITS loop direction, which by the radial-cycle-2 coedge pairing is the reverse, `P[m], ..., P[0]`. Forward and 1-forward-reversed are the SAME unordered point set, so the two meshes coincide vertex-for-vertex on `E`. `mesh_open_ratio` counts unmatched shared-edge points; here there are none, so it is zero with NO weld / merge / heal.
> - **Extension to the band's two rims.** The band has two shared rims `E_lo`, `E_hi`, each independently satisfying the above with its own wall coedge. The interior rows are face-private (Q1.2) and appear on no shared edge, so they contribute nothing to `mesh_open_ratio`. Therefore the band is watertight on BOTH rims by the SAME argument applied twice, with no interaction between them.
> - **Extension to the cap-with-NURBS-rim.** The cap shares ONE NURBS rim (same argument) and contains a pole, which is a single shared contraction vertex (dossier 64), used once by the cap and once by any neighbour across the seam slit, again the same point. So the cap is watertight on its rim and at its pole.
> **Limitations.** The identity holds only if BOTH faces genuinely read the SAME stored polyline (not two independent resamplings of the same curve, which would differ in floating point). The construction forbids resampling: the wall and the band both read `fin_curve_samples` off the EdgeId. If a code path ever resampled, watertightness would fail; the invariant is "shared edge => read the stored polyline, never resample."
> **Kernel relevance.** This is the watertightness proof the prompt asks for, and it is the SAME proof as Add.281's window-disc, applied twice (two rims) and once more at the pole (cap). The proof is by construction (shared point set), not by tolerance, so it is robust across sphere frames and ops. **Verified** against the OCCT / Patrikalakis edge-once rule and the Add.281 precedent.

### Q3.2 Why orientation (forward vs reversed) does not perturb the point set

> **Citation.** Half-edge / radial-edge coedge pairing (de Berg et al., computational geometry; Weiler radial-edge); dossier 64 Q2.2 (band loop orientation).
> **Method / Content.** A shared edge is traversed in OPPOSITE directions by its two coedges (the manifold pairing, or radial-cycle-2 for the non-manifold case). The mesh polyline is an ORDERED sequence, but watertightness is a SET property: `{P[0], ..., P[m]}` equals `{P[m], ..., P[0]}`. Reversing the traversal reverses the index order but not the point set, so the two faces' shared-edge vertices match as a set, which is all `mesh_open_ratio` requires. The orientation matters for the FACE winding (outward normals, Q1.1 step 7) but is invisible to the shared-edge point-set equality. This is why "forward vs 1-forward reversed" (the Add.281 phrasing) is watertight: the 1-forward shift plus reversal is a relabeling of the same vertices.
> **Limitations.** If a face inserted an extra vertex on the shared edge (e.g. a midpoint refinement on only one side), the sets would differ and watertightness would fail. The construction forbids per-face refinement of a shared edge; refinement, if ever needed, must update the canonical EdgeId polyline so BOTH faces see it.
> **Kernel relevance.** Closes the proof: orientation is a winding concern, not a watertightness concern, so the band's forward / reversed rim traversals are watertight by set equality. **Verified** (set vs sequence distinction; the coedge pairing is standard).

## Q4. Validation: `mesh_open_ratio` ~ 0 and `mass == mesh` on probe_wrap geometry

### Q4.1 The probe_wrap test family and the two independent gates

> **Citation.** Keel `mesh_open_ratio` and `mass == mesh` gates (internal, dossier 63 for the mass gate design); dossier 64 Q5 (the analytic band oracles); spherical-zone / cap closed forms, https://mathworld.wolfram.com/Zone.html and dossier 63 section 3.3.
> **Method / Content (the validation matrix).** Two ORTHOGONAL gates, because the band has two independent obligations:
> - **Watertightness gate (`mesh_open_ratio` ~ 0).** For each probe_wrap case, after meshing the band and its caps, assert `mesh_open_ratio == 0` exactly (every shared-edge point matched). This is a STRUCTURAL check independent of geometry: it passes iff the shared-polyline-read invariant (Q3.1) holds. It must pass for ALL three boolean ops (union, intersection, difference) and across multiple sphere frames (axis-aligned, tilted, off-origin) because the invariant is frame-independent. A single unmatched point is a hard fail.
> - **Mass gate (`mass == mesh` within the 2 percent curved band).** The band's exact volume / area come from the spherical-zone closed form when the rims are latitudes, or from dossier 63's analytic sphere-zone reference for the general wrap (gate the analytic mass against the closed form, demote the mesh to the loose witness, dossier 63 section 3). The interior density (face-private, Q1.2) is set by the dossier-63 sagitta rule plus the equal-area correction so the meshed band volume lands inside the band. This gate is about interior density only; it cannot affect watertightness.
> **The non-regression requirement (explicit).** The circle-rim baseline (latitude rims, the existing clip case) and the window-disc baseline (Add.281 single rim) must NOT regress: run them through the NEW stencil path and assert identical or better `mesh_open_ratio` and `mass == mesh` results. The circle-rim case is the stencil with `c_lo`, `c_hi` as `v = const`, so it MUST reproduce the old clip's mesh exactly (or pass the same gates); the window-disc is the cap path (Q2.3) and must reproduce Add.281.
> **Limitations.** The `mass == mesh` band for the general non-latitude wrap relies on dossier 63's analytic sphere-zone reference being available for the wrap geometry; where it is not, the gate falls back to a tighter interior mesh with headroom (dossier 63 bucket b). The watertightness gate has no such dependency and is always available.
> **Kernel relevance.** Separates the two validation concerns the prompt lists: watertightness (`mesh_open_ratio`, structural, all ops / all frames) and mass (`mass == mesh`, density, dossier 63), with an explicit no-regression clause on the circle-rim and window baselines. **Claimed** as the validation plan; the closed-form oracles are **verified** (standard spherical-zone formulae).

### Q4.2 The exact oracle for the first milestone

> **Citation.** Spherical zone area `2*pi*R*h` (lune-free zone between two parallel planes at axial distance `h`); spherical-cap volume `(pi*h^2/3)(3R - h)`, https://mathworld.wolfram.com/SphericalCap.html ; dossier 64 Q5 (banding oracle pattern).
> **Method / Content (exact oracle for the narrowest slice).** A sphere radius `R` cut by a coaxial cylinder radius `r < R` (the simplest sphere-cylinder wrap). The intersection is two latitude-like circles (here exactly latitudes when coaxial) at `v = +-arcsin(sqrt(1 - r^2/R^2))`. The band between them is a spherical zone: lateral area `2*pi*R*h` with `h = 2*R*sin(arcsin(...))` the axial height, and the enclosed-solid volume is the closed-form spherical zone / barrel volume. The two caps are spherical caps with the closed-form cap volume. **Oracle:** mesh the band and two caps, assert `mesh_open_ratio == 0` (watertight on both rims and both poles) and `mass == mesh == 2*pi*R*h` (area) / closed-form zone volume, for all three ops, with fragment count out = 3 (band + 2 caps) = kept-face count in. This is the COAXIAL case (rims are exact latitudes), the bridge from the existing circle-rim clip to the general stencil: it must pass through the new stencil path identically, proving no regression, before the non-coaxial NURBS-rim case is attempted.
> **Limitations.** The coaxial case has latitude rims, so it does not yet exercise the non-planar wrap; it is the REGRESSION oracle, not the new-capability oracle. The new-capability oracle is the NON-coaxial sphere-cylinder wrap (Q4.3).
> **Kernel relevance.** Gives an exact, fully analytic oracle for the regression slice, ensuring the stencil reproduces the circle-rim clip before generalising. **Verified** (spherical zone / cap closed forms).

### Q4.3 The new-capability oracle (non-coaxial wrap)

> **Citation.** Sphere-cylinder intersection (non-coaxial), https://en.wikipedia.org/wiki/Sphere%E2%80%93cylinder_intersection ; dossier 64 Q3 (closed-form preimages) and Q5.3 (the non-planar wrap oracle pattern).
> **Method / Content.** A sphere radius `R` and a cylinder radius `r` whose axis is OFFSET / TILTED from the sphere center: the intersection is a non-planar wrap (a single encircling closed curve, or two, depending on offset). The band between two such wraps (or the cap inside one wrap) has a volume computable by the dossier-63 analytic boundary-flux integrator over the trimmed band, cross-checked against a dense-mesh reference (the dossier-63 three-side gate). **Oracle:** `mesh_open_ratio == 0` (the watertightness gate, exact, the primary new-capability check) and `mass == mesh` within the 2 percent band (the density gate), for all three ops, across tilted / offset sphere frames. The watertightness gate is the load-bearing one: it directly tests that the non-planar NURBS rim's `fin_curve_samples` are shared identically between the band and the cyl wall, which is the exact Add.283 decline being closed.
> **Limitations.** The non-coaxial volume has no elementary closed form in general (it is an elliptic-integral-class quantity), so the `mass == mesh` side uses the analytic-vs-dense-mesh cross-check (dossier 63) rather than a pinned constant; the WATERTIGHTNESS side is exact and independent of any volume formula, which is why it is the primary gate for this milestone.
> **Kernel relevance.** This is the oracle that converts the Add.283 sphere-wrap decline from DECLINE to PASS. The watertightness gate is exact and frame-independent; the mass gate rides on dossier 63. **Claimed** (the oracle plan); the watertightness gate is exact by construction.

## Patent awareness

- **Even-odd / Jordan-curve point-in-polygon and scanline fill** are textbook computational geometry (pre-1980), no patent. The Hormann-Agathos (2001) and arXiv:1207.3502 (2012) papers are robustness refinements of a public-domain method, freely implementable. **PREFER.**
- **OCCT `BRepMesh` (EdgeDiscret two-stage edge-then-face meshing, seam / degenerate-edge handling)** is LGPL open source; the edge-discretized-once structure is documented and freely usable. Keel may follow it directly. **PREFER.**
- **Patrikalakis-Marshall robust trimmed-B-spline tessellation (1998)** is a published IEEE paper; the edge-once-transfer rule is a published algorithm, not a patent grant. Implement from the paper. **PREFER.**
- **The "strip between two parametric curves" ruled-mesh fill** (Lai et al. and classical ruled-surface theory) is published / classical, no patent. **PREFER.**
- **Spherical zone / cap closed forms and sphere-cylinder intersection** are classical mathematics, public domain. **PREFER.**
- **Post-2006 trimmed-NURBS RASTERIZATION patents flagged.** US20070018988A1 ("Method and applications for rasterization of non-simple polygons and curved boundary representations") and the older Sun trimmed-B-spline rendering patents (US 5,226,115 / 5,303,386 / 5,353,389 / 5,363,478 / 5,243,694, all GPU trimming-curve rendering) are CLAIM-READING HAZARDS only for GPU / rasterization-pipeline trimming, a different mechanism than Keel's CPU `(u, v)` even-odd stencil with a shared-polyline boundary band. Keel's stencil is the classical scanline / point-in-polygon on the CPU parameter domain, which is pre-1980 prior art; the watertightness comes from the shared canonical EdgeId polyline, not from any rasterization trick. This is a clean design-around. **AVOID copying GPU trimming-curve rasterization claims; PREFER the classical CPU scanline + shared-edge-polyline path.**
- **DiagSplit (2009) crack-free adaptive tessellation** is a published academic method (ACM TOG); its split-dice non-isoparametric crack-avoidance is interesting but NOT needed here, because Keel achieves crack-freedom by the simpler shared-canonical-edge-polyline rule (the edge is discretized once and both faces read it), not by matching adaptive tessellation factors across a shared edge. No patent flagged on the math; Keel does not adopt the mechanism. **INVESTIGATE only if Keel ever moves to per-face adaptive tessellation factors that must match across edges; otherwise N/A.**

Net: **build on the LGPL OCCT edge-discretized-once structure, the published Patrikalakis edge-once-transfer rule, the classical CPU even-odd scanline, and classical ruled-strip fill; the shared canonical EdgeId polyline gives watertightness by construction. The path is clear of post-2006 GPU-rasterization claim-reading risk.**

## Synthesis: ADOPT / AVOID / INVESTIGATE

**ADOPT.**
- **The even-odd `(u, v)` stencil for `tessellate_sphere`** (Q2): the direct sphere analog of the landed cylinder `(theta, h)` stencil. Build the canonical interior grid, keep grid points strictly between the two rims by a +`v` (wrap-safe) even-odd ray test, hand pole-terminated columns to the cap path. Retire the circle-rim-specific clip as the `v = const` special case of this stencil.
- **The shared canonical rim polyline read by both faces** (Q3): the band and the cyl / cone wall both read the rim's `fin_curve_samples` off the EdgeId (forward on one side, reversed on the other). This is the Add.281 window-disc invariant applied to the two band rims, and it makes `mesh_open_ratio` zero by construction.
- **The face-private interior with a boundary-band zipper to the fixed rim** (Q1): interior rows are private and never inserted on a rim; the boundary band zippers the rim polyline to the adjacent interior row by a two-pointer strip merge, so the interior density is a pure `mass == mesh` decision (dossier 63) decoupled from the wall.
- **The cap-with-NURBS-rim as band-column-plus-window-disc-fan** (Q2.3): a cap is the pole-terminated column handled by the already-landed Add.281 fan to the single pole anchor, with the single rim handled by the same shared-polyline boundary band. No new mechanism.
- **The two-gate validation** (Q4): `mesh_open_ratio == 0` (structural, all ops / all frames) AND `mass == mesh` within the 2 percent band (density, dossier 63), with an explicit non-regression clause on the circle-rim and window-disc baselines.

**AVOID.**
- **Clipping the full-sphere grid against the rim** (the DEAD END): the circle-rim-specific clip is the thing being generalised; do not extend the clip, replace it with the stencil.
- **Resampling a shared rim curve independently on the band and the wall.** Two independent resamplings of the same curve differ in floating point and break watertightness. The invariant is: shared edge => read the stored `fin_curve_samples`, never resample.
- **Inserting any vertex ON a shared rim from the face-private interior.** That breaks the shared-point-set equality. The boundary band must terminate ON the rim's existing vertices, inserting none.
- **A +`u` keep-test ray** (it must wrap the seam and count a re-entry crossing). Use the +`v` ray, which never crosses the `u`-seam.
- **Doubling the pole cover or evaluating at the pole** (undefined normal). The pole is a single shared contraction vertex; perturb off it (dossier 64 Q4).
- **Copying GPU trimming-curve rasterization** (patent hazard). Use the classical CPU scanline.

**INVESTIGATE.**
- The tolerant even-odd crossing convention on the periodic f64 `(u, v)` domain: the half-open edge rule (arXiv:1207.3502) at shared `v` values, the ray-through-vertex degeneracy, and a rim tangent to the +`v` ray, all feature-relative.
- Whether the canonical `fin_curve_samples` density set at imprint time is always >= the grid `v`-spacing where the rim turns (Q2.2 limitation); if not, either densify the rim at imprint or DECLINE the band rather than mis-fill.
- Whether neighbouring bands / caps on the same sphere should share interior column positions at the seam slit (Q1.1 step 2 uses the canonical column set to enable this), and whether that buys any cross-face benefit beyond determinism.

**RECOMMENDED FIRST MILESTONE (narrowest honest slice with an exact oracle).**
**The COAXIAL sphere-cylinder wrap: a sphere band between two latitude rims, meshed by the NEW stencil path, reproducing the existing circle-rim clip exactly.** Concretely: take `tessellate_sphere`, route the latitude-rim case through the new even-odd `(u, v)` stencil (with `c_lo`, `c_hi` as `v = const`), mesh the band plus two caps, and assert `mesh_open_ratio == 0` and `mass == mesh == 2*pi*R*h` (spherical-zone area) / closed-form zone volume, for all three ops, fragment count out = 3 = kept-face count in. This is the smallest slice that exercises the stencil, the shared-rim-polyline invariant, the boundary-band zipper, and the cap path, while having a fully analytic exact oracle (spherical zone / cap formulae) and a hard regression guard (it MUST reproduce the circle-rim clip). It introduces the stencil without yet taking on the non-planar wrap, so a failure is unambiguously a stencil bug, not a preimage bug. Only after it passes is the non-coaxial NURBS-rim case (Q4.3) attempted, which closes the Add.283 decline.

**FOLLOW-UP LADDER.**
- Rung 1 (first milestone): coaxial sphere-cylinder, latitude rims, through the new stencil, `mesh_open_ratio == 0` and `mass == mesh`, reproducing the circle-rim clip (regression guard).
- Rung 2: the window-disc baseline (Add.281 single rim) re-routed through the cap path (Q2.3), reproducing Add.281 (second regression guard).
- Rung 3: NON-coaxial sphere-cylinder wrap (offset axis), the genuine non-planar NURBS rim, band + 2 caps, `mesh_open_ratio == 0` (exact, the primary gate) and `mass == mesh` via the dossier-63 analytic-vs-dense cross-check, all three ops, tilted / offset frames. This is the Add.283 DECLINE-to-PASS.
- Rung 4: sphere-CONE wrap (the cone wall returns the same rim points), same gates.
- Rung 5: multi-rim sphere (>2 wraps, several bands), iterating the stencil along sorted rim crossings (dossier 64 Q1.1 banding feeding the mesh).
- Rung 6: NURBS-vs-NURBS sphere wrap (recovered-NURBS rim with the SameParameter bound, dossier 64 Q3.4), the general frontier.

**DECLINE-forever set (the tessellation view of dossier 64 Q4).**
- A rim tangent to a pole (the fan triangles degenerate; the contraction is ill-defined): DECLINE, never emit a degenerate fan.
- A rim whose `(u, v)` preimage self-crosses (the even-odd parity is ill-defined; the band is not a simple region): DECLINE.
- A sub-tolerance sliver band (the boundary band has no room for an interior row; the mesh is ambiguous): DECLINE rather than emit a sliver that risks `mass != mesh`.
- A rim crossing the seam slit at a point coincident with a pole (the identification and contraction collide): DECLINE.
- A canonical `fin_curve_samples` density below the grid turn-resolution that cannot be raised within budget (Q2.2): DECLINE rather than mis-fill the scanline.
