# Kernel-Layer Literature Research: Index

Deep literature research on the topics a CAD geometry kernel needs beyond curve/surface mathematics: topology, operations, system engineering, and adjacent representations. Companion to the NURBS collection in `docs/research/nurbs/` and the original six tracks in `docs/research/`. Roughly 1090 cited sources across forty-two dossiers plus two capability maps (Parasolid, XNURBS), in the same full-findings format (per-source citation, explicit mechanism, limitations, kernel relevance). Files 39 (coincident/tangent face booleans), 40 (blend/fillet surface generation), 41 (blend overflow and radius-vs-feature failures), and 44 (concave-fillet topology surgery) were direct, on-critical-path requests from the implementation team. Files 42-43 are a non-English-language pass (Russian C3D/Golovanov, Chinese CAGD and domestic kernels) checking whether the English-only corpus left gaps. Files 01-10 are the first round; files 11-20 cover topics surfaced by that round; files 21-24 are the third round closing literature gaps; file 25 is an authoritative Parasolid capability audit (144 items) and files 26-28 are the fourth round closing the operation gaps that audit confirmed; files 29-30 are the dirty-geometry round (Parasolid's strongest, most-differentiating capability); file 31 is an XNURBS capability audit and files 32-33 are the surfacing round it drove; files 34-37 are the engineering round (testing/corpus, verification, performance, numerical substrate) that shifts from what the kernel does to how it is made fast and proven correct; file 38 is the STEP AP242 import dossier, the one shippable-path literature gap the completeness audit (docs/research/03-completeness-audit.md) flagged.

## Headline findings across the collection

1. **The topology hierarchy is a solved consensus.** Parasolid, ACIS, OCCT, and STEP ISO 10303-42 describe essentially the same body-shell-face-loop-fin-edge-vertex model; fin = coedge = half-edge = oriented edge-use under four names. Adopt it without re-derivation (file 01).
2. **Go non-manifold from day one, via the partial entity structure.** PES gives radial-edge expressiveness at roughly half the storage; Parasolid makes regions first-class (the model to emulate), ACIS bolts cellular topology on (cautionary), OCCT refuses non-manifold boolean results (the gap) (file 02).
3. **Tweak is the foundation local operation.** Parasolid and ACIS both implement offset/move/taper/delete-heal/blend-removal as clients of change-face-surfaces-and-reintersect. OCCT lacks it entirely: a clear differentiator target for Keel (file 03).
4. **Delete-face cannot be decomposed** into simpler edits and must remain a dedicated primitive (Zou-Feng-Gao 2023 variational direct modeling) (file 03).
5. **Constraint solver above the kernel, profile geometry inside.** Siemens ships DCM beside Parasolid; one arrangement-plus-winding-number engine unifies region extraction, curved planar booleans, and offset cleanup inside the kernel (file 04).
6. **Watertight faceting is a by-construction property:** discretize each model edge once, have both adjacent faces consume the same polyline. All three industrial faceters converge on this (file 05).
7. **One multivariate spline solver unifies interrogation.** Silhouettes, draft isoclines, isophotes, curvature extrema, umbilics, and projection are all zero-set queries against the same subdivision solver already mandated by the intersection research (file 06, ties to nurbs/04).
8. **Persistent naming reduces to per-entity lineage.** Every scheme from Kripac (1995) to Cascaval's PLDI DSL (2023) is a variation on (operation id, operand ids, derivation kind: created/modified/split/merged/deleted). The kernel must emit these events from every operation, and must be deterministic, or no naming layer can be built above it. This must be settled before the topology layer freezes (file 07).
9. **Copy-on-write persistent topology buys three features at once:** undo, atomic failure rollback (a failed boolean must not corrupt the model), and cheap journaling snapshots. Parasolid's deltas and ACIS's bulletin boards are both approximations of what a Rust persistent data structure gives natively (file 07).
10. **Robustness claims need a corpus and a pass rate.** fTetWild's run-over-all-of-Thingi10K methodology plus the ABC dataset (1M B-reps) give Keel a concrete acceptance benchmark. Compiler FMA fusion can silently break orientation predicates; pin FP contraction and use Shewchuk predicates (file 08).
11. **Generational-index arenas are the Rust answer to entity references.** Parasolid tags, Fornjot's object store, and a generational arena are the same idea; it sidesteps borrow-checker pain on cyclic topology graphs and gives stable save/load references (file 08).
12. **Indirect predicates (Cherchi/Attene) give exact mesh booleans without bignum-everywhere.** EMBER's plane-based representation is architecturally sympathetic to B-rep (faces already carry carrier geometry). Parasolid Convergent Modeling's lesson is architectural: make mesh faces a first-class face type in the same topology (file 09).
13. **Lattices belong on the implicit side; winding number is the universal inside/outside oracle** across B-rep, mesh, and implicit, including leaky geometry (file 09, ties to nurbs/06).
14. **The grazing condition v.n = 0 unifies swept volumes and the medial axis** (envelope of moving solid; envelope of inscribed balls). One pruned MAT with a radius field feeds five services: midsurface, wall thickness, shelling validity, mesh sizing, defeaturing (file 10).
15. **Midsurfacing remains commercially unsolved** (2025 papers still propose new methods); treat it as a service with explicit failure reporting, not a guaranteed operation (file 10).

## Headline findings, second round (files 11-20)

16. **Exactness has a sharp affordability gradient by algebraic degree.** Circles and conics are genuinely exactness-affordable; quadric intersections are rational-when-singular and need one square root in the smooth case (QI); NURBS is effectively unbounded. CAD models are degeneracy-dense by design, exactly where floating-point filters fail. No shipped kernel delivers the consensus "exact topology + tolerant geometry" hybrid: Keel's opening (file 11).
17. **The witness method solves 3D constraint diagnosis.** There is no Laman analog in 3D, but for direct modeling the live B-rep IS a valid witness configuration, so a single Jacobian rank test gives correct over/under/well-constrained diagnosis. Langbein's beautification is an open-literature equivalent of Live Rules (file 12).
18. **Minimal-motion is THE direct-modeling solver requirement:** enforce detected regularities exactly while minimizing change from the current configuration (minimum-norm step, frozen null space). The same principle unifies solving, beautification, and symmetrization (file 12).
19. **All commercial healers converge on stitch, then simplify (analytic recognition), then geombuild (gap tightening).** Heal-vs-tolerate is a policy choice, and tolerant entities are contagious through booleans, arguing for a prefer-exact bias on boolean-bound bodies. Surface extension is the shared core of delete-face healing, tweak, and untrimming, and must be bounded and validated (file 13).
20. **Bitwise determinism is achievable but must be designed in:** FMA contraction can make orientation predicates non-antisymmetric (pin ffp-contract off on predicate code), system libm is the largest cross-platform hole (use correctly-rounded math), HashMap ordering and lossy decimal serialization are the residual Rust traps. Exact double round-tripping in files is load-bearing for persistent naming (file 14).
21. **Feature recognition's persistent hard problem is intersecting features**, and every era converges on the same answer: propose (hints or ML), then exactly verify in the kernel. ML benchmark accuracy is synthetically inflated; the kernel's job is to expose the attributed adjacency graph, exact surface classification, and a volumetric verifier (file 15).
22. **The assembly tier is universally a definition/occurrence DAG** with geometry stored once and transforms on references. The kernel obligations are stable edit-surviving IDs and keeping geometry in local frames (never bake far-from-origin world transforms into body coordinates) (file 16).
23. **Tolerance zones are offset geometry** (Requicha), and MMC/LMC virtual boundaries are offset solids, so the offset machinery is tolerance-critical. Datum establishment per Y14.5.1 is an existential optimization requiring Chebyshev/min-zone fitting, not just least squares. The dominant industry failure is semantic PMI loss on exchange, which again lands on persistent entity references (file 17).
24. **The patent landscape is navigable but has three active HIGH-risk zones:** Synchronous-style constraint inference during direct edits (Siemens, to ~2034), mixed mesh/B-rep in one body (convergent modeling, ~2035+), and U-splines (~2037). The original T-spline patent expired March 2024. The entire classical core (NURBS, Euler ops, booleans, classic blends, tessellation) is patent-safe. Recommended: MIT OR Apache-2.0 dual license for the patent grant (file 18).
25. **Parallel feature-history regeneration is an open gap:** industrial regeneration speed comes from caching and dependency pruning, not parallelism (a documented negative finding). The regeneration layer is a scheduler over deterministic, lineage-reporting, snapshot-able, fail-soft kernel operations; everything else stays above the kernel (file 19).
26. **Sheet metal reduces to an anchored bend graph that supports cycles**, with topology invariant between flat and folded states, thickness-paired faces as first-class citizens, exact cylindrical unwrap in the kernel, and bend compensation (K-factor, DIN 6935) as a pluggable rule layer, never kernel physics (file 20).

## Headline findings, third round (files 21-24)

27. **The motion data contract is uniform across engines:** MuJoCo, Drake, and Bullet all consume mass+inertia per body, joint axis+type, and collision geometry. The kernel's motion obligations are exactly those plus joint-axis extraction from face pairs and time-parameterized swept volumes. Effective mobility needs rank-based se(3) computation, not Gruebler joint counting (file 21).
28. **CAx-IF/LOTAR validation properties are the comparison keystone:** implementing volume/area/centroid/cloud-of-points natively gives Keel both the cheap stage of its own testing oracle and interoperability with every commercial model validator. All comparison methods (fingerprints, graph matching, learned encoders) consume the same kernel primitives: deterministic mass properties, controllable surface sampling, and an attributed adjacency graph (file 22).
29. **One orthogonal-distance fitting core serves four subsystems.** Datum simulation, healing simplify, reverse engineering, and canonical recovery are configurations (objective: L2/min-zone/MIC/MCC, robustness mode, constraint set) of a single fitting library. Exact optimality certificates exist (Voronoi for roundness, contact alternation for min-zone), so results can be certified, not just computed. Metrology mode forbids the outlier rejection that RE mode requires (file 23).
30. **The linear line complex is the universal axis recognizer:** one 6x6 eigenproblem on surface normals classifies cylinder vs revolution vs helix and recovers the axis, with pitch as the branch variable. Keel's recognition input is a noise-free spline (closed-form curvatures), removing the dominant error source in the scan-oriented literature. Substitution must be topology-coordinated (neighboring faces converted to the same analytic) per OCCT's design lesson (file 24).

## Parasolid coverage audit (file 25) and fourth-round findings (files 26-28)

A 144-item inventory of Parasolid PK functionality (file 25) was mapped against the full corpus. The result: the corpus already covers the large majority of Parasolid's surface (creation, all booleans including convergent, local operations, hollow/shell/offset, sweep/spin/loft, sheets, mesh/lattice, tessellation, HLR, all interrogation, tolerant modeling, attributes, sessions/rollback/XT, healing, simplification, canonical conversion, midsurface, Euler ops). Only three operation areas were uncovered or thin, and the fourth round closed them:

31. **N-sided surfaces require central-split, not a single patch.** For n != 4, or any irregular-valence node in a curve network, the four-corner twist structure plus Peters' vertex-enclosure parity constraint make a single tensor-product NURBS that is G1/G2 to all boundaries impossible; the n-gon must be split into n quad NURBS subpatches around a central point (what shipping kernels emit). The easy cases convert exactly: Coons and Gordon B-spline surfaces collapse to one NURBS, GB patches with polynomial boundaries to rational Bezier. The G1/G2 hole-fill primitive is a concrete 6-step procedure (file 26).
32. **Deform the control net, hold the parameter domain: trim curves and pcurves survive by construction.** This is the load-bearing B-rep deformation insight, absent from the graphics literature, and the reason to push NURBS control points rather than sample-and-refit. Barr's normal rule n' = det(J)(J^-1)^T n keeps normals, offsets, and draft correct under any differentiable deformation; Gain-Dodgson injectivity (det J > 0 in Bezier form) is the validity certificate. Green coordinates are the most CAD-relevant cage scheme (quasi-conformal). Emboss and wrap are composed operators (offset+trim+stitch; reverse-flatten then emboss), which argues for building flattening as a bidirectional map. Analytic faces promote to NURBS under deformation: it is the inverse of file-24 recovery (file 27).
33. **One spine + spring-curve + polymorphic-section engine serves fillets and chamfers alike.** The cross-section is the only variable: line for a chamfer, arc for a fillet, conic-by-rho for shaped, curvature-spline for G2. Chamfer is the linear member of the section family, not a separate code path, though it should keep an exact straight ruling. Parasolid and ACIS converge on the same overflow menu (smooth/cliff/notch/auto) and blend-graph sequencing, confirming the architecture is industry-standard. Hold-line blends are the engine run inverted (contact curve given, radius solved per section), so the section solver must be bidirectional. Vertex blends, overflow, and small-radius-vs-tolerance are the documented dominant failure modes (file 28).

## Dirty-geometry round (files 29-30) and XNURBS surfacing round (files 31-33)

The dirty-geometry round addresses what the user identifies as Parasolid's single strongest, most-differentiating capability: bad input still gets a usable answer where other kernels fail or decline.

34. **Correctness and robustness-on-dirty-data are orthogonal axes.** CGAL is exact but brittle (refuses imperfect input); OCCT is correct but all-or-nothing by default (its fuzzy boolean value is the only openly documented industrial knob, and a blunt one); Parasolid and ACIS manage tolerance automatically and return valid-but-salvaged bodies. The graceful path is a six-rung escalation cascade (filtered-exact, tolerant, fuzzy/widened-snap, controlled perturbation, virtual topology, mesh/SDF floor) under two hard rules: geometry is negotiable and reported, topology validity is non-negotiable. Qi-Shapiro epsilon-solidity gives a result a property to certify against ("valid epsilon-solid for reported epsilon"). The deepest finding: robustness is largely an organizational asset, the regression corpus (C3D's 500k+ models) is the real engine, and it is the one moat an open project can plausibly out-build (file 29).
35. **Virtual topology is the strongest tolerate-by-hiding technique:** treat a cluster of bad/tiny faces as one composite face without touching the geometry. Zero shape error, reversible, cannot create new self-intersections, so it belongs before any geometric repair on the mesh/query paths. Generalized winding numbers plus fTetWild form a robustness floor that mathematically cannot fail to return a valid manifold, with fidelity bounded by a caller-chosen envelope. Snapping must be a one-shot clustered union-find merge with per-merge local validation, never an unbounded relaxation loop (file 30).

The XNURBS round followed the Parasolid pattern: catalog (file 31) then research the one distinctive uncovered capability.

36. **XNURBS-class surfacing is variational, and it is the same engine the fitting research already converged on.** A single global energy minimization (membrane plus thin-plate fairness, Welch-Witkin 1992) over arbitrary mixed constraints, discretized to a control-point quadratic, reduces to (N^T W N + lambda K) P = N^T W Q subject to A P = b: data term, fairness penalty, and pure-variational solve are one engine at different weights, independently confirming the nurbs/03 fitting conclusion. The documented wavy-interior failure mode is explained directly: hard boundaries plus an under-weighted fairness term. Use transfinite (file 26) for clean fast N-sided fills, variational for messy/over-determined cases, with transfinite as the variational warm start (file 32).
37. **Matching a fixed neighbor surface linearizes to pinned control-point rows.** The bilinear G1/G2/G3 inter-patch conditions (DeRose, Liu-Hoschek) become linear when the neighbor is fixed: G1 pins one interior control-point row, G2 pins two, G3 pins three, which is exactly the Alias practical rule (degree 5 for G2, degree 7 for G3). The whole constraint machinery collapses to one KKT-solved constrained least squares with the file-32 fairness matrix, dirty input is absorbed as weighted soft constraints with slack (never infeasible, ties to files 29-30), conflicts are caught by rank-revealing factorization, and impossible corners (Peters vertex-enclosure from file 26, in algebraic form) are demoted to least squares (file 33).

## Engineering round (files 34-37): how it is made fast and proven correct

This round shifts axis from what the kernel computes to how it is built, tested, and run. It operationalizes the corpus-is-the-robustness-engine thesis (finding 34) that the rest of the research kept arriving at.

38. **Robustness is generated, not hoped for: the corpus must be built to break the kernel.** Public datasets (ABC, Thingi10K, Fusion 360 Gallery) are clean by construction and under-sample exact coincidence, which is measure-zero for random generators, so synthetic adversarial generators that snap geometry into tangency and coincidence are non-optional. Shrinking must target the construction recipe toward the degenerate witness, not perturb coordinates away from it. fTetWild's run-over-the-whole-dataset pass-rate (they report 98.7% on Thingi10K) is adopted as Keel's headline robustness metric, and every found failure becomes a permanent named golden case (file 34).
39. **The oracle problem is solved by invariants, not answers.** Without ground truth, correctness is checked by metamorphic relations: boolean algebra laws, round-trips, invariance under rigid transform and uniform scale, and the strongest of all, invariance under knot refinement and degree elevation (they perturb the internal representation while holding the modeled object fixed). Mass-property inclusion-exclusion and the topology validator are continuous oracles. The decisive layering: an epsilon-solidity certificate (Qi-Shapiro) becomes proof-grade only when its epsilon is bounded by a validated-numerics enclosure (Krawczyk, interval/affine) rather than estimated, and an exact oracle on the easy linear/low-degree cases breaks differential-testing ties when OCCT itself is the buggy reference. Formal verification realistically reaches predicates and small algorithms, not whole booleans (file 35).
40. **A kernel is a data-parallel numerical engine bolted to a serial graph-mutation engine, and copy-on-write is the keystone that lets both be true.** Intersection and classification read immutable COW snapshots lock-free; only the build/stitch phase serializes, the split OCCT (BOPAlgo) and Parasolid both independently reach. The determinism-versus-speed conflict has a rigorous resolution: binned/order-independent reduction (ReproBLAS) plus parallel-map-then-deterministic-merge (handle-sorted, no hash-order, no float reassociation) gives bitwise-identical results across thread counts while keeping work-stealing. The same no-reassociation rule blocks naive autovectorized reductions, so reductions need explicit fixed-order kernels. GPU is display-only: its float non-reproducibility is incompatible with the determinism promise on the exact-modeling path. Bezier extraction is the highest-leverage SIMD decision (branchy de Boor becomes a branch-free SoA GEMM) (file 36).
41. **The numerical substrate: sparse-direct by default, QR over normal equations, analytic derivatives over autodiff, portable interval widening.** Sparse direct Cholesky/QR (CHOLMOD lineage, now native in Rust via faer) beats tuned multigrid at kernel problem sizes and allows factor reuse, so it is the surfacing-solver default; the lambda-K fairness term doubles as a Tikhonov regularizer that conditions the system so plain Cholesky works. Spline structure gives analytic hodograph derivatives that beat autodiff where available. Rust rounding-mode control is awkward (LLVM assumes round-to-nearest, WASM lacks the instruction), so interval arithmetic should default to portable ULP-widening rather than FPU-mode flipping, which also helps determinism (file 37).

## STEP AP242 import (file 38): the one remaining shippable-path literature gap

42. **STEP import is a close-but-treacherous entity mapping, and the parser should be a focused pure-Rust build.** STEP's B-rep model maps almost one-to-one onto Keel's hierarchy (manifold_solid_brep to Body, closed_shell to Shell, advanced_face to Face, edge_loop to Loop, oriented_edge to Coedge, edge_curve to Edge, vertex_point to Vertex), but the high-risk pitfalls are: rational-NURBS weight pre-multiplication into homogeneous 4D (the silent-distortion trap), the orientation algebra (XOR of advanced_face.same_sense, face_bound.orientation, oriented_edge.orientation, and edge_curve.same_sense), seam edges on periodic surfaces appearing twice in one loop (one Edge, two Coedges), pole/degenerate faces via vertex_loop, non-normalized direction vectors, pcurve reconstruction when STEP gives only the 3D edge, and units plus the file's own uncertainty_measure_with_unit global tolerance (a STEP file declares its own accuracy, which seeds Keel's per-entity tolerance floor). Verdict: build a focused pure-Rust Part 21 tokenizer plus two-pass resolver over a hand-curated ~60-entity dictionary (borrow ruststep's Holder/tables pattern), do not FFI to OpenCASCADE or STEPcode, and treat OCC's reader plus its ShapeFix sequence as the conformance reference. Import is where Keel's tolerant/heal machinery (files 13, 29, 30) first meets foreign dirty data, and the CAx-IF validation properties (volume/area/centroid, file 22) are the round-trip check (file 38).

## Coincident and tangent face booleans (file 39): an M7b-critical-path request from the implementation team

43. **Coincident faces are preserved, not perturbed away, and the on-on classification reduces to two tables keyed on relative sense.** The Laidlaw-Trumbore-Hughes regularized-boolean rules, identical in outcome to Requicha-Voelcker set-membership and Mantyla nbr classification, say: a same-sense coincident overlap survives union and intersection (kept exactly once, its duplicate dropped), an opposite-sense overlap survives difference; everything else drops or reverses. The winding number is undefined exactly on a shared boundary, resolved by a two-sided epsilon-along-normal neighborhood test. Production kernels all share a gluing fast path (OCCT BOPAlgo GlueShift/GlueFull, Parasolid matched regions, ACIS prepare) that declares faces coincident so SSI is skipped, roughly 90% time saved on abutting input. The decisive philosophy split: Simulation of Simplicity perturbs coincidences away, but in CAD a flush mating face is design intent that must be preserved, so Keel keeps SoS only as a symbolic tie-break for which copy survives, never to erase coincidence. The genuinely hard residual is the NURBS overlap-region boundary, where canonical recovery (file 24) is a hard dependency and the tolerant path is the fallback (file 39).

## Blend/fillet surface generation (file 40): an M7b-critical-path request from the implementation team

45. **A constant-radius fillet is a canal surface along a spine, and the spine is the SSI of the two offset support surfaces, which makes the analytic cases fall out for free.** Offsetting each support face inward by r stays in-family (plane to plane, cylinder to coaxial cylinder, cone to coaxial cone, sphere to concentric sphere, torus to torus), so the spine is an analytic surface-surface intersection Keel already computes, and the blend is the envelope of spheres of radius r along it. The exact-analytic ladder: a straight spine gives a cylinder (plane-plane), a circular spine gives a torus (many plane-cylinder, plane-sphere, coaxial cases), natural-quadric pairs give a Dupin cyclide, and everything else is a NURBS canal approximated to tolerance by skinning radius-r section circles in rotation-minimizing frames. The cyclide verdict: do not add a primitive type, emit cyclides as exact rational biquadratic NURBS, keeping cylinder and torus as the fast exact path. G1 is automatic (the ball is tangent to both faces along the spring curves), and the spring curves are exact pcurves on both surfaces by construction. The trim-and-stitch is a local imprint (ties file 39, kernel/03), and all three production kernels use a declarative blend-recipe/blend-graph pattern; notably OCCT emits NURBS even for plane-plane, the gap Keel's exact ladder closes (file 40).

46. **The medial axis predicts every fillet failure: the maximum safe radius is the local feature size.** Overflow and radius-vs-feature, the dominant fillet failure modes, were elevated to a first-class treatment. The unifying result: r_max(t) = dist(spine(t), medial axis) = local feature size, and all eleven catalogued failure modes (self-intersection, off-face-end, roll-on, cross-feature, cliff, notch, thin-wall pinch, swallow-feature, blend-blend interference, vertex, over-large radius) reduce to the single medial inequality r > dist(spine, something), with 1/kappa_concave as a cheap local pre-filter, half-wall-thickness for pinch, and inter-ribbon distance for blend-blend. The design move is a pre-generation feasibility pass that samples the spine, queries local feature size, and emits a per-parameter radius ceiling and an overflow map BEFORE any surface is built, gating file 40's generator. The recovery policy is best-effort with full disclosure (predict, then roll-on or smooth, then radius-limit, then setback/cap/notch, then partial-plus-report, and only as last resort reject), always returning a valid body plus structured per-region diagnostics, the graceful-degradation doctrine (file 29) applied to filleting. Parasolid and ACIS are recovery-oriented with named overflow modes but keep the predictor internal; OCCT is rejection-oriented and fragile; Keel should expose the feasibility pass and offer named recovery (file 41).

## Non-English pass (files 42-43): does the English-only corpus leave gaps?

The whole corpus was built from English sources. This pass searched Russian and Chinese natively to test whether that cost anything. Honest verdict: the gap is small, the corpus already held the substance, but two genuinely new, directly-actionable items surfaced, both on the tolerant-modeling and architecture axes where C3D and the Chinese effort are strongest.

47. **C3D's tolerant-topology model is the cleanest tolerant-B-rep specification found in any language, and it is directly implementable.** From the Russian-only C3D Labs engineering blogs (the corpus had only ever cited C3D as the 500k-model robustness benchmark, never mined it for algorithmic detail): tolerance is bound to the TOPOLOGICAL entity, not the geometry. A tolerant vertex is a sphere of radius t, a tolerant edge is a tube of radius t, and the carried curve or surface stays exact inside that envelope. This sharpens Keel's existing per-entity-tolerance decision (D2) into a concrete geometric model, and pairs with two secondary C3D findings: per-operation boolean precision as a first-class API argument, and connectivity repair by tolerant-vertex insertion. The rest of the Russian material (topology structures, boolean engine, variational constraints, Soviet spline theory) the English corpus already had at equal or greater depth, and Golovanov's book has an authorized English translation, so it was never truly hidden (file 42).
48. **The Chinese journals hide no robustness silver bullet, but the domestic-kernel engineering and one intersection result are new.** A targeted search for a Chinese-only robust-boolean or self-intersection breakthrough returned nothing the corpus lacks; the Chinese practitioner literature converges on the same geometry-topology-consistency root cause (file 29) and the same OCCT all-or-nothing critique, which is corroboration, not novelty. What is genuinely new: the domestic-kernel picture, where Overdrive (ex-US VX) and CRUX (ex-Japan UEL) are acquired-and-domesticated and only AMCAX/Jiushao (USTC, 2017-2025) is a publicly-described from-scratch kernel, and it made the notable architectural inversion of building T-mesh splines as the foundational layer with NURBS B-rep added later. AMCAX independently choosing GMP plus MPFR plus TBB corroborates files 36-37, and ZWSOFT calling fillet/blend the kernel's "Mount Everest" independently confirms the three-dossier blend bet (28, 40, 41). The one adoptable algorithm nugget: a 2024 derivative-free curve-intersection iteration with order-2 convergence on tangential contact (2x-4x speedup exactly in the contact case file 39 flags as hardest), plus the PIA/LSPIA fitting lineage and its constrained CG-CLSPIA variant mapping onto files 32-33 (file 43).

## Concave-fillet topology surgery (file 44): an M7-tail-critical-path request from the implementation team

49. **A concave fillet grows the cap face and is the make-dominant dual of the convex kill-dominant dissolve; unify the two on a single convexity sign.** The convex fillet shrinks the cap face (split off the corner triangle, dissolve into the blend via kef then kev); the concave fillet does the opposite, the cap face grows, the reentrant corner vertex becomes interior, and the boundary extends out to the blend end-arc, so the convex split-off-and-dissolve is the wrong operation and yields a valid solid with the wrong volume. The grow-to-arc sequence (split_edge twice to land the spring curves, mev plus mef to build the exterior lune and the single blend face, kev to collapse the arc helper, kef twice to merge the lune, kev to absorb the reentrant corner) is each a GWB operator with a fixed delta, so Euler-Poincare is preserved at every step. The recommendation is one unified pipeline that forks only at the cap on the convexity sign sigma = sign((n1 x n2).t), Keel's equivalent of OCCT ConcaveSide: sigma > 0 cap-shrink-dissolve, sigma < 0 cap-grow-splice, with the spine/spring/offset signs already correct from file 40. Use in-place loop-regrow for the clean degree-3 plane-plane cap (exact, code-shared with convex), and fall back to bead-construct-and-sew for multi-face caps, into-face/into-blend ends, and mixed-convexity ends, sewing the tangent spring seam by file 39's two-sided method as a tolerant edge (file 42's tube-of-radius-t model). All three production kernels confirm the pattern: one pipeline with a convexity classifier that extends rather than trims the support faces at the concave extremity (file 44).
